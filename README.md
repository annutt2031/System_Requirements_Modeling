# System Requirements Modeling

Проект посвящён графическому и табличному моделированию требований к информационным системам.

Для анализа используются две предметные области:

- система онлайн-записи в барбершоп;
- система управления доставкой заказов.

Одна и та же система рассматривается с нескольких сторон: движение данных, взаимодействие ролей, последовательность действий и жизненный цикл объектов.

## Кейс 1. Онлайн-запись в барбершоп

Система позволяет клиенту выбрать услугу, мастера и свободное время.

Также она поддерживает:

- расписание мастеров;
- записи клиентов;
- уведомления;
- фиксацию выполнения услуги;
- оплату;
- отзывы;
- передачу финансовых данных во внешнюю систему.

## Кейс 2. Сервис доставки

Система объединяет поставщиков, оператора, курьера, диспетчера, администратора и бухгалтерию.

Ключевые функции:

- регистрация и обработка заказов;
- публикация свободных заказов;
- бронирование курьером;
- изменение статусов;
- переназначение проблемных заказов;
- фиксация доставки;
- передача данных в бухгалтерию;
- получение информации о начислениях.

## Использованные модели

В проекте требования представлены сразу несколькими типами моделей.

### DFD — Data Flow Diagram

Используется для отображения:
- внешних участников;
- процессов;
- информационных потоков;
- хранилищ данных.

### Swimlane Diagram

Показывает последовательность действий и распределение ответственности между пользователями, системой и внешними участниками.

### Extended Swimlane

Расширяет процессную модель и показывает не только действия, но и создаваемые или изменяемые в ходе процесса данные и документы.

### State Diagram

Используется для описания жизненного цикла объекта и переходов между его состояниями.

### State Table

Табличное представление переходов:
- исходное состояние;
- инициатор;
- событие;
- условие;
- новое состояние.

## Структура проекта

### `ex00_BARB_dfd.docx`

DFD уровня 0 для системы онлайн-записи.

Показаны потоки данных между клиентом, мастером, менеджером, системой уведомлений, бухгалтерией и внутренними хранилищами.

Модель охватывает запись на услугу, управление расписанием, оказание услуги, оплату, отзывы и уведомления.

### `ex00_DLVR_dfd.docx`

DFD уровня 0 для системы доставки.

Отображает движение информации о заказах, курьерах, статусах доставки и начислениях между участниками системы и хранилищами данных.

### `ex01_BARB_swd.docx`

Swimlane-диаграмма процесса онлайн-записи.

Действия распределены между:
- клиентом;
- системой;
- мастером;
- менеджером.

Показан процесс от выбора услуги и времени до оказания услуги, оплаты и получения отзыва.

### `ex01_DLVR_swd.docx`

Swimlane-диаграмма доставки.

Показано взаимодействие:
- администратора;
- системы;
- курьера;
- диспетчера;
- оператора;
- бухгалтерии.

Модель охватывает регистрацию курьера, ввод заказа, бронирование, доставку, изменение статусов, переназначение и передачу данных для расчётов.

### `ex02_BARB_adswd.docx`

Расширенная Swimlane-модель онлайн-записи.

К процессу добавлены создаваемые и используемые артефакты:
- карточка услуги;
- реестр записей;
- расписание;
- данные оплаты;
- отзыв клиента.

### `ex02_DLVR_adswd.docx`

Расширенная модель процесса доставки.

Дополнительно отражены:
- реестр заказов;
- данные бронирования;
- статусы;
- начисления;
- история переназначений;
- данные пользователя.

### `ex03_BARB_dst.docx`

Диаграмма состояний для объекта предметной области барбершопа.

Показан жизненный цикл мастера с точки зрения его доступности:
- вне смены;
- доступен;
- забронирован;
- оказывает услугу.

Отражены события и роли, инициирующие переходы.

### `ex03_DLVR_dst.docx`

Диаграмма состояний курьера в системе доставки.

Отражает переходы от регистрации и проверки до активной работы, выполнения заказа, возникновения проблемы и блокировки.

### `ex04_BARB_tst.docx`

Таблица состояний объекта «Запись на услугу».

Описаны переходы:
- новая;
- подтверждена;
- отменена;
- неявка;
- выполнена.

Для каждого перехода указаны инициатор, событие и условие.

### `ex04_DLVR_tst.docx`

Таблица состояний заказа.

Описан жизненный цикл:

`Создан → Свободен → Забронирован → В доставке → Доставлен`

Также предусмотрены состояния:
- проблема;
- отменён.

## Результат

Набор моделей позволяет проверить требования с разных точек зрения и обнаружить несогласованности между ролями, процессами, данными и состояниями объектов.

### Использованные нотации

`DFD` · `Swimlane Diagram` · `State Diagram` · `State Table` · `AS IS / TO BE`
